# 输入与计算约定

以 `examples/assembly/scenario.json` 和 `config.json` 为可运行模板。所有数组必须显式提供；没有报价、在途或审批时使用空数组。JSON 不接受重复字段、NaN 或 Infinity。

## 数据集

| 字段 / 拆分文件 | 主要字段 |
|---|---|
| `order` / `order.json` | `order_id`、`customer_id`、日期、仓库、`snapshot_at`、`status=CONFIRMED`、`lines` |
| `materials` / `materials.json` | 唯一 `material_id`、名称、`material_type`、`base_uom=PCS`、关键等级、检验等级、`active` |
| `bom_items` / `bom_items.json` | `bom_id`、`bom_version`、父项、子项、`qty_per`、`scrap_rate`、单位、有效期、发布状态 |
| `inventory_positions` / `inventory_positions.json` | 物料、仓库、批次范围、现存、冻结、待检、已分配、安全库存、快照时点 |
| `inbound_supply` / `inbound_supply.json` | 唯一行号、物料、仓库、订购/已收/取消量、预计到货日、状态、快照时点 |
| `substitution_rules` / `substitution_rules.json` | 原料、替代料、转换系数、最大替代比例、适用产品、有效期、审批角色 |
| `suppliers` / `suppliers.json` | 唯一供应商编号、名称、准入状态、有效期、准交率、合格率、服务分 |
| `supplier_quotes` / `supplier_quotes.json` | 唯一报价编号、供应商、物料、单价、币种、MOQ、包装倍数、产能、交期、有效期、税运口径、来源引用 |
| `approval_decisions` / `approval_decisions.json` | 唯一审批编号、范围、对象、决定、角色、人员类型/编号、时点、数量上限、意见、证据引用 |

订单行必须包含 `line_id`、`product_id`、正整数 `ordered_qty`、`uom=PCS`、`bom_id` 与 `bom_version`。成品及子组件分别使用 `FINISHED`、`SUBASSEMBLY`；叶级外购件使用 `PURCHASED`。

库存表应是所选仓库的完整快照：未出现的物料按零库存处理，不能用“不知道库存”的空表替代真实导出。现存量和各扣减量为非负整数，合计扣减不得超过现存；同一物料、仓库、批次范围不得重复。

## 日期与版本

- `runtime.as_of_date` 是固定的计划日期，`runtime.generated_at` 是带时区偏移的计划时点；两者本地日期须一致。
- 订单快照不得来自未来，且不能超出 `max_snapshot_age_hours`。库存及在途快照必须与订单快照一致。
- 订单指定顶层 BOM 编号与版本。递归子组件必须有唯一有效的已发布 BOM，缺失或多版本冲突均报错。
- 物料需求日为交付日减去 `material_need_offset_days`，使用自然日。
- 未确认、缺少到货日、晚于需求日或承诺日期已过但仍未收货的在途，不计入按期供应。

样例使用固定的 2026-11-16 时点，因此未来重跑仍可得到相同结果。分析新快照时应一起更新配置时点和业务快照。

## 数量规则

```text
每条 BOM 边需求 = ceil(父项需求 × 单件用量 × (1 + 损耗率))
可用库存 = 现存 − 冻结 − 待检 − 已分配 − 安全库存
未收在途 = 订购 − 已收 − 取消
替代前缺料 = max(毛需求 − 可用库存 − 按期在途, 0)
剩余缺料 = 替代前缺料 − 已批准替代抵扣
```

不同路径的叶级需求求和，保留各自来源。此版本按每条边取整，不是将所有路径合并后只取整一次。库存按照 `allowed_warehouses` 指定的仓库池汇总；需要限制为单一仓库时，只配置该仓库。

子组件始终继续展开，其已有库存不参与抵扣。跨订单共享库存不是本工具的全局状态，调用方需先完成分配并提供相应快照。

## 替代料与审批

`conversion_factor` 表示抵扣一件原料所需的替代料数量；`max_share_percent` 的分母是原料的**替代前缺料**。替代库存先保留自身 BOM 需求，再在同次计划中共享，不能重复占用。

审批对象格式为 `SUB-{order_id}-{source_material_id}-{substitute_material_id}`。审批需要：

- `scope=SUBSTITUTION`、`actor_type=HUMAN`、`decision=APPROVE`。
- 配置与规则要求的全部角色，以及人员编号、时间、意见和证据引用。
- 正整数 `max_source_qty`，表示该审批允许抵扣的原料数量上限。

应用数量不超过所有所需角色给出的最小上限；同一对象的上限不能因多条规则被重复使用。任一人工拒绝决定阻断应用。审批是输入记录，不是工具代办的审批。

同一原料服务多个产品时，规则必须覆盖其全部需求产品，或使用明确的 `*` 适用范围；否则该规则不应用。此版本不自动推定不同产品之间如何分配替代额度。

## 报价和草稿

报价须为 CNY、每 PCS 单价，且明确含税、含运费。币种不符、已过期、供应商准入失效、质量/准交率不达标或产能不足的报价保留淘汰原因。

```text
建议采购数量 = ceil(max(剩余缺料, 最小起订量) / 包装倍数) × 包装倍数
价格分 = 最低合格单价 / 本报价单价 × 100
交期分 = max(0, 100 − 迟延天数 × 扣分系数)
总分 = 价格分、交期分、质量分、服务分的加权和
```

这是单价加权比较，不是整单总成本优化；会同时显示采购量、超买量和估算金额供复核。金额按 Decimal 四舍五入到分。无合格报价时，价格和供应商为 `null`，缺料仍保留。

达到金额阈值或属于关键物料的草稿行，要求采购经理和财务审批。检验衔接中的 `EXAMPLE_PLAN_*` 是样例占位规则，应由使用方提供实际检验方案。

## 记录与导出

相同输入与配置得到相同计划标识；任何配置或输入变化会改变标识。原始输入、配置和审计记录分别带有 SHA-256 指纹。哈希链只检查文件内部的一致性，不能证明人员身份、外部事实或抵抗整链重写。

每次输出使用新的目录。校验失败不生成计划；存储故障可能留下部分文件，应使用新目录重跑。业务数据、运行输出和密钥应保存在仓库外，或默认忽略的 `data/`、`outputs/` 中。
